# Rekt Brawl bet arena

Bots fight, people bet on who wins in REKT, ETH or the stablecoin. Every screen runs the same
seeded fight, and anyone can replay a round and check the winner.

## How a round works

1. **Open.** The operator commits `seedHash = keccak256(serverSeed)` and picks two fighters and a stage.
   Betting stays open for `BET_SECS` (45 s by default).
2. **Bets.** Each currency has its own pool. Winners in a currency split that currency's losing pool,
   pro rata. Every bet is folded into a rolling `betsHash`.
3. **Lock.** The operator reveals `serverSeed`. The contract sets
   `fightSeed = keccak256(serverSeed, id, address(this))` and `fightStart = now + 5 s`.
4. **Fight.** Every browser runs `fightSeed` through the same engine, synced to the chain clock.
   People who join late fast-forward to the live moment.
5. **Settle.** The operator replays the fight headless (`fightsim.js`) and settles the winner once the
   fight has ended on screen. People then claim their winnings.

If the operator stalls for an hour after lock, **anyone** can call `expire()` and every bet is refunded.

## Checks that were run

- **Same fight on every engine:** 1,092 fights replayed identically in V8 (Chrome, Node) and
  JavaScriptCore (Safari). They matched on winner, frame count and path hash. Fight code now uses a
  seeded RNG, and sin/cos are built from `+ - * /`, because engines disagree in the last bit of
  `Math.sin`.
- **Contract:** 41 forge tests, including fuzzing and reentrancy. The suite was mutation-checked
  by breaking the contract 11 ways, and every break was caught.
- **Full loop on a private anvil chain:** `node test/e2e_local.js 2`. It deploys, runs the real
  operator, places 10 bets a round across three currencies from five wallets, and checks every
  claim against an independent payout calculation. It also checks where the cut goes (REKT to
  dEaD, the rest to treasury), confirms the arena is left with only dust, and runs `verify.js`
  on each round.

## Before going live: what Duane decides

- **Stablecoin.** Circle does not list USDC on Robinhood Chain. The chain's stablecoin is USDG,
  which Pons v2 quotes in. The contract takes any ERC20 address in the stable slot, and the page
  labels it from `live.json`.
- **REKT address.** Available once REKT is launched. Call `setRekt(addr)`.
- **Cut** (`CUT_BPS`, max 1000). The cut comes from the losing pool only, so a winner never gets
  back less than they staked. The REKT cut is burned. The ETH and stable cut goes to `TREASURY`,
  for buybacks. The page never mentions it.
- **Operator key.** Use a fresh hot key with a little gas and nothing else. It must never bet: it
  knows the seed before `startFight`.
- **Hosting.** The operator is a long-running process, for example on the `lw` box next to
  api.sin.run. The page with the live arena needs its own domain. The claude.ai artifact stays in
  practice mode, because wallets don't inject into it.

## Going live (after the decisions above)

```
cd chain
OWNER=… OPERATOR=… TREASURY=… STABLE=… REKT=… CUT_BPS=… \
  forge script script/Deploy.s.sol --rpc-url https://rpc.mainnet.chain.robinhood.com --broadcast --private-key <deployer>
```

Then write `arena/live.json` and rebuild. The page switches from practice to live:

```json
{ "rpc": "https://rpc.mainnet.chain.robinhood.com", "chainId": 4663, "chainName": "Robinhood Chain",
  "explorer": "https://robinhoodchain.blockscout.com", "arena": "0x…",
  "tokens": { "ETH": "0x0000000000000000000000000000000000000000", "USDC": "0x…", "REKT": "0x…" },
  "decimals": { "ETH": 18, "USDC": 6, "REKT": 18 }, "stableSymbol": "USDG" }
```

Run the operator:

```
RPC_URL=https://rpc.mainnet.chain.robinhood.com ARENA=0x… OPERATOR_KEY=0x… TOKENS=<stable>,<rekt> node operator.js
```

Check any round:

```
node verify.js https://rpc.mainnet.chain.robinhood.com 0x<arena> <roundId>
```

## Rules for anyone editing the game

Anything that changes how a fight plays out changes who wins. That covers moves, stats, AI,
items, stages and physics. So:

- Bump `ARENA.version` in `62_rules.js`, and keep the old `fightsim.js` so old rounds can still
  be replayed.
- Visual code (`70_render.js`, `9x_v3_*.mjs`) must never call `rand()` or `irand()`, and must never
  write fight state. Use `Math.random()` or `vrand()` for visuals.
- Rerun `node test/det_node.js` and `jsc test/det_jsc.js` after any change to fight code.
